# 活动专区

入口为 /activities/；首页导航在 BenchList 后提供“活动专区”。活动首页现在列出两个独立专题：

- /activities/skill-audit/：2026-11-12 Skill 评测归因看板。43 条案例均含原始提问、历史回答、完整诊断、全部原评测理由，以及归因使用的 300 个结构化业务事件（含 160 次模型请求）；按公共前缀恢复模型消息上下文。用户明确确认公开访问和完整具体案例，不作业务内容脱敏或概括替代，上游既有凭据遮蔽标记保留。43 个案例及索引 JSON 只存开发机和 R2，不提交 Git；配置只记录白名单路径、字节数及哈希。筛选、搜索、按需载入、直达链接、SHA-256 校验与深色模式在浏览器运行。历史归因与 5 次真实新重跑分别展示。
- /activities/vibemotion/：保留既有 VibeMotionBench 六屏路演及所有视频素材。视频按点击加载，支持全屏及 HTTP Range。

/activities 和 /activities/skill-audit 会以 308 跳转到对应的带尾部斜杠地址，保留 query；未列出的路径不做通配跳转。

## UI 增量发布

活动模块不改变题库数据。Worker 的 `src/site-overlay.js` 是从人工审阅的路径清单生成的模块：

- 只在 `PUBLIC_RELEASE_ID` 与清单的 `base_release` 完全一致时启用。
- 只有逐条列出的 `site/` 文件从新 release 读取，没有目录通配或旧对象回退。
- 每个对象的长度和 SHA-256 元数据须匹配，否则返回 503；不存在则返回 404。
- `/data/`、`/assets/`、BenchList 和未列出的 UI 文件继续读取原来经过完整验证的 release。
- 新版本仍只有 `PUBLIC_CORPUS` 与 `PUBLIC_RELEASE_ID` 两个 bindings；通过 Version Upload / Deployment API 发布。
- 回滚只需把 100% 流量切回上一 Worker version，无需删除或覆盖任何对象。

上传新增清单中的所有对象，核对完整增量 inventory 的对象集合、大小、SHA-256 和 HTTP metadata，
读取所有新增线上文件验证真实字节，然后销毁一次性上传密钥并删除临时 route/Worker。
必须回读全部 Worker modules 并与已提交源码逐字节比对，然后才能切换生产流量。

以后发布完整 corpus 时，将本模块合入完整的 `site/` 导出并移除或更新 overlay；
不得只更改 base_release 以套用未重新核验的增量清单。旧数据与增量对象均须保留供回滚。

完整案例 payload 位于被 Git 忽略的 site/activities/skill-audit/cases/。重建 overlay 必须使用开发机固定候选材料，普通代码克隆不会自动取得这些业务数据。v3 引用闭包明确列出 87 个 JSON（43 份原案例、43 份 Trace Atlas 结构化证据、1 份索引），不允许目录通配。原始 Trace 二进制归档不属于本站发布闭包；结构化提取范围及其限制在逐案材料中保留。
